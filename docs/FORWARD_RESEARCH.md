# Forward research evidence contract

`research:forward` is a separate, read-only qualification workflow. Its private store holds evidence and append-only capture ledgers. It does not connect to PostgreSQL, change S3, submit transactions or enable economics. The existing [saved-data audit](RESEARCH_QUALIFICATION.md) is a legacy diagnostic and cannot supply an independent witness.

## Trust and storage

An operator approves and pins a `solaris-forward-1` trust policy before any study is frozen. The policy contains `version`, `network` (`mainnet` or `fixture`), `genesis`, `authorities` and `layouts`. Mainnet is pinned to the [Solana mainnet genesis hash](https://github.com/solana-labs/solana/blob/master/sdk/src/genesis_config.rs). Each authority has an `id`, an `organization`, `roles`, and an Ed25519 SPKI PEM `publicKey`. An operator must verify that the two archival organizations have separate custody and upstream data. Two keys or endpoints at one organization count once. Duplicate keys across identities are rejected. A layout has the on-chain `program` and the approved `idlDigest` of the exact IDL bytes. The default unconfigured policy has no approved sources or layouts. Study design and signature trust change by digest, never by silently replacing this policy.

The external signers attach detached Ed25519 signatures over UTF-8 canonical JSON of `{version,kind,issuer,policy,body}`. `policy` is the canonical policy SHA-256. The envelope adds `signature` as padded base64. Canonical JSON recursively sorts object keys, preserves array order, and uses ECMAScript JSON string and number serialization. Hashes are lowercase hexadecimal SHA-256. All monetary integers in evidence are decimal strings in raw units unless a signed RPC witness contains a safe native JSON integer. Timestamps are UTC `YYYY-MM-DDTHH:mm:ss.sssZ`. Evidence-signing keys are independent attestation keys. SOLARIS has no command to sign an attestation and does not accept private keys or wallet credentials.

`init` creates a new private directory. `artifact` adds raw proof bytes under their SHA-256. `import` checks signatures before adding up to 256 envelopes from a JSON file. Each stored JSON object has a content-derived filename, is atomically added once, and is checked again during replay. Proof artifacts, signed records, manifests and request reservations stay private. Keep the store on a protected local filesystem and back it up for independent audit. Append-only writes and content hashes detect file alteration during replay. They cannot protect against an administrator deleting the entire store. A checkpoint pins the exact member list and exposes a digest, so a later replay cannot silently omit a member of that checkpoint.

## Evidence records

| Kind and role | Body and verification |
| --- | --- |
| `block` from `chain` | `genesis`, `slot`, `parentSlot`, `blockhash`, `previousBlockhash`, `blockTime`, ordered signature `roster`, `transactions` and optional `membership`. Each selected transaction has `signature`, `wire` (base64), `fee`, `outcome`, raw `meta`, and `metaDigest`. Two independent organizations must agree on the block identity and roster, and separately on a selected transaction's wire and metadata. Each legacy/v0 signer signature is checked against the signed message. The message's recent blockhash is never treated as the containing block. |
| `segment` from `chain` | `genesis`, `root`, `blockCount`, `firstSlot`, `lastSlot`, `parentSlot`, `parentHash`, `lastHash`, `firstTime`, `lastTime`. Operators run `segment` over the same normalized ordered headers, each with `slot`, `parentSlot`, `blockhash`, `previousBlockhash`, `blockTime`, `rosterHash` (canonical hash of the ordered roster). The command checks parent links and time order and computes a Merkle commitment. Odd leaves are paired with themselves. `segment ... INDEX` emits `{root,index,siblings}` for a matching block's `membership` array. Each signed segment covers at most 8,192 slots. Independent segment attestations establish the complete finalized path inside each segment. The report checks joined segments, start and end anchors, contradictions and membership for every landed attempt. Both periods must share a continuous or overlapping finalized path. |
| `gap` from `chain` | `slot`, `status` (`missing`, `unavailable`, or `skipped`). Skips also specify `before`, `after` and a `segment` digest binding both blocks' membership. A skip clears only when an agreed child points directly to the agreed parent across that slot. Unsigned capture records keep slot and selected-transaction gaps separately. A header can resolve slot availability. Resolving a selected transaction needs an agreed receipt or its absence from the agreed roster. |
| `deployment` from `history` | `program`, `programData`, `binaryDigest`, `idlDigest`, `evidenceDigest`, `activation`, `fromSlot`, `untilSlot`. A reference (`activation`, `creation`, or a landed attempt) includes `slot`, `blockhash`, `signature`, `outerIndex` and `innerIndex` (`-1` for outer). The successful loader transaction must match the Program and ProgramData accounts at the correct ABI positions. `fromSlot` is the first slot after the activation slot. The signed historical replay artifact must establish the executable binary and the entire half-open interval through `untilSlot`. Conflicting intervals block adjudication. |
| `pool` from `history` | `address`, `venue`, `baseMint`, `quoteMint`, `baseVault`, `quoteVault`, `vaultOwner`, `baseTokenProgram`, `quoteTokenProgram`, `creation`, `fromSlot`, `untilSlot`, `evidenceDigest` and `recipients: [{account,owner,role}]`. Check the successful creation instruction and official account positions. The artifact must establish the mints, account authority, state interval and authorized fee destinations at the historical slot. A native Pump.fun quote uses the System Program and the WSOL mint as the SOL unit identifier. |
| `census` from `census` | `plan`, `window`, `segment` (canonical segment body digest), `scannedAt`, `evidenceDigest`, and `attempts`. One independent attempt census per segment per window. Store every observation under the frozen selection rule, including unsuccessful or missing outcomes. Each attempt has `id`, `pool`, `side`, `decisionAt`, `status`, and `evidenceDigest`. `success` and `failed` must include the complete transaction reference. Other states are `missing`, `unavailable`, and `not_landed`. The census artifact must identify the scan inputs and provide a reproducible full census, including successful transactions that must be adjudicated or explicitly rejected. |
| `quote` from `market` | `plan`, `attempt`, `pool`, `side`, `status`, `requestAt`, `sourceAt`, `receivedAt`, `captureDigest`. An `observed` quote includes `validUntil`, `stateDigest`, `routeDigest`, `inputMint`, `outputMint`, `inputAmount`, `outputAmount`, `liquidity`, and `priceImpactBps`. Clock-stamp the signed quote digest as it is observed. `no_route` and `unavailable` are recorded failed inputs and cannot qualify a successful fill. Preserve price, liquidity, impact, observed latency and route state as they were available at decision time. |
| `decision` from `strategy` | `plan`, `attempt`, `pool`, `side`, `decisionAt`, `quote` (signed quote digest). Seal this outcome-free intent independently after the quote and by `decisionAt`. Attempts cannot retroactively select a favorable observation time. A sealed decision omitted from the census blocks completeness. The strategy, quote, clock and census roles have separate trust checks. |
| `timestamp` from `clock` | `subject` is the content digest of the manifest record, signed quote or signed decision envelope. `at` must come from the independent timestamp authority's observed UTC clock. The authority's organization cannot also attest any study-data role. A plan must be observed strictly before development starts. Importing the receipt later preserves its original signed timestamp. |
| `fill` from `execution` | `plan`, `attempt`, complete transaction reference, `wireDigest`, `metaDigest`, `decision`, `method: "independent-replay-v1"`, and `replayDigest`. A rejection includes `reason` (`unsupported`, `ambiguous`, `insufficient_evidence`, or `conflicting`). An acceptance includes `side`, `trader`, `deployment`, `poolProof`, `ownerProof`, `feeProof`, `base`, `quote`, `quoteMode`, `recipientTransfers`, `networkFee`, `feePayer` and `lamportMovements`. The reviewer must be independent of the chain and historical witnesses and the attempt census. |

Transfer edges have `mint`, `tokenProgram`, `decimals`, `source`, `destination`, `sourceOwner`, `destinationOwner`, `debit`, `credit`, `withheld`, and `movementIndex` (CPI index in the same outer group). Token-2022 also requires `tokenFeeProof`, including the mint extensions and effective epoch fee rule. Scoped transfer verification uses the current supported Pump layouts and independently matches the raw SPL CPI bytes and endpoints. Unaccounted descendant movements involving the trade's accounts reject the adjudication. Fixed-role or additional recipient claims must match a historically authorized `recipientTransfers[].role` (`protocol`, `creator`, `buyback`). A claim's source and destination amounts must reconcile exactly as `debit = credit + withheld`. Historical participant ownership and independent parser output live in the proof artifacts.

`quoteMode` is `token-replay`, `wsol-replay`, or `native-replay`. For a directly debited native sell, the edge uses `movementIndex: null` and the independent runtime replay must establish exact lamport payouts at the scoped invocation. The transaction-wide ledger must reconcile every RPC lamport balance after the separate network fee. `lamportMovements` entries have `kind`, `source`, `destination`, `amount` and `evidenceDigest`. Supported kinds are `native_swap`, `native_fee`, `wsol_transfer`, `wrap_funding`, `unwrap_refund`, `rent_deposit`, `rent_refund`, and `unrelated`. Lifecycle transfers inside the candidate require their CPI coordinates. Ambiguous, unsafe or truncated cases stay excluded. The report publishes counts and hashed pool labels. It does not publish raw signatures, accounts, quotes or quantities.

## Freeze, acquire, replay, monitor

```sh
npm run research:forward -- init .solaris/forward-evidence
npm run research:forward -- policy /private/research/policy.json
npm run research:forward -- artifact .solaris/forward-evidence /private/proofs/strategy.md
npm run research:forward -- freeze .solaris/forward-evidence /private/research/policy.json /private/research/plan.json
npm run research:forward -- import .solaris/forward-evidence /private/research/policy.json /private/evidence/signed-bundle.json
npm run research:forward -- checkpoint .solaris/forward-evidence
npm run research:forward -- report .solaris/forward-evidence /private/research/policy.json MANIFEST_SHA AS_OF_UTC CHECKPOINT_SHA
npm run research:forward -- watch .solaris/forward-evidence /private/research/policy.json MANIFEST_SHA 60 10
```

The plan contains `version`, `policy`, `study`, the artifact digests `strategy`, `selection`, `feeModel` and `exclusions`, `maxQuoteAgeMs`, `maxObservedLatencyMs`, `horizonMs`, and `windows: {development,forward}`. A window defines midnight-UTC `from` and exclusive `until`, and `pools: [{address, venue, baseMint, quoteMint}]`. Freeze both windows and their asset universe before collecting outcomes. Selection, permitted fees and exclusion rules must be in the pinned artifacts. The scope is this prospectively declared pool universe. The result cannot claim coverage of all Solana activity. Each window requires 30 UTC days with strict eligible data, at least 20 pools and 200 unique strict-fill signatures, with at most 20% from one pool. The windows cannot share pool addresses, base mints, signatures or decision identities. Scope checks purge potential holding periods that cross a window boundary. Market data and commitments must precede landing. Proxy labels, unsigned captures and fixtures cannot seed qualification.

The provider-independent import supports authorized offline archival exports even without an RPC endpoint. The optional direct capture accepts a private JSON request file with `slots: [{slot, signatures: []}]` and optional `maxRequests`, `maxUnits`, `retries`. Always use a dedicated source and a verified no-cost entitlement. `SOLARIS_ARCHIVE_FREE_ACCESS=yes` declares that entitlement and `SOLARIS_FREE_ARCHIVAL_RPC_URL` supplies the HTTPS endpoint through the environment. Set them locally without logging the endpoint. The tool performs finalized `getBlock` and `getGenesisHash` only. It does not activate a plan or use any of the collector's existing endpoints by default.

```sh
npm run research:forward -- capture .solaris/forward-evidence /private/research/policy.json SOURCE_ID /private/research/requests.json
npm run research:forward -- segment /private/research/policy.json /private/evidence/headers.json 0
```

Limits per store are one collector, at least one second between requests, at most 64 requests and 128 weighted units per run, and at most 256 requests and 512 weighted units per UTC day. A genesis check costs one local unit, a block roster four and a full block sixteen. These are conservative local accounting weights, not a provider billing guarantee. The collector reserves units before contacting the source and charges retries. Defaults allow zero retries, and the hard retry cap is two transient attempts after the initial request. Each response is limited to 32 MiB and each request to 15 seconds. `429` persists a shared cooldown and defers the remaining slots. A crashed active collector fails closed. Check the process has exited before clearing only its empty `.collector-active` lease directory. Use one store for a collection deployment so the durable limits are not split across stores.

`report` is deterministic for the same checkpoint, manifest, policy and `AS_OF_UTC`. Without those arguments it evaluates current evidence available in the store. `watch` only reads local files and prints changed reports. It runs at most 120 checks at 30–3,600 second intervals, and stops when the verdict changes to ready or a technical failure. Both commands report open gaps, quote and decision commitments, coverage per pool and UTC day, independently adjudicated instructions and unique holdout signatures. A successful report is still research-only. The S3 status and trading guards remain separate.

## External requirements

The two externally approved archival operators must supply matching finalized block commitments and full selected transaction bytes and metadata retaining historical loader activity, token balances, account lookup addresses, fees and CPI traces. A generic current-state RPC or the existing collector cannot establish independent archive custody. Larger chronological ranges should use bounded brokered/offline exports and segment commitments. Independently approved authorities must provide historical deployment/IDL artifacts and pool/recipient account states, scoped execution adjudications, complete attempt censuses, decision-time route and liquidity evidence and signed timestamps for the plan, quotes and decisions. Legacy/v0 transactions and supported Pump layouts are the automatic adjudication scope. V1 wire transactions, unsupported loaders/venues/variants, absent historical extension state or unresolved direct payout accounting remain explicitly blocked or reviewer-rejected. None of these authorities or data sources are assumed to exist merely because the tool is installed.

Underlying formats are documented by [Solana getBlock](https://solana.com/docs/rpc/http/getblock), [transaction structure](https://solana.com/docs/core/transactions/transaction-structure), [Loader v3 instruction definitions](https://docs.rs/crate/solana-loader-v3-interface/latest/source/src/instruction.rs), [Pump.fun IDL](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json), [PumpSwap IDL](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump_amm.json), and [Token-2022 transfer fees](https://solana.com/docs/tokens/extensions/transfer-fees).
