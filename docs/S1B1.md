# SOLARIS S1b.1 — Conservative DEX Swap Decoder (v0.3.0)

**Scope:** no trades, no wallets, no external RPC, no keys. Uses already hydrated transaction JSON from `onchain_transactions`. The existing `recorder` and `stream` services are unchanged; results go into a new derived table `onchain_trade_decodes`.

Source references (verify on upgrades):
- https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json
- https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump_amm.json
- https://solana.com/docs/rpc/json-structures

Supports Anchor discriminator + official account layout for *legacy* Pump.fun `buy`, `sell`, `buy_exact_sol_in`, and PumpSwap `buy`, `sell`, `buy_exact_quote_in`. Pump.fun v2 variants are explicitly detected but **not** decoded as legacy layouts. Other DEXes, unknown variants, and ambiguous/compound transactions are not forced into BUY/SELL classifications.

## Classification semantics

- `failed_onchain`: transaction meta.err was non-null. **Never** trade success.
- `unsupported_dex`: no Pump.fun/PumpSwap instruction detected, may still be a trade on another venue.
- `unrelated_pool`: Pump instruction refers to a different pool from the one observed.
- `unsupported_variant`: Pump program but unknown/unsupported instruction layout.
- `ambiguous`: cannot establish signer, watched pool, token account or base delta, or multiple Pump instructions in one transaction.
- `direction_only`: one supported Pump instruction, signer and user base-token-account delta agree on direction; quote amount/price **not proven**. This is the expected ceiling for Pump.fun native-SOL trades in v0.3.0.
- `matched_quote_delta`: for a PumpSwap instruction, signer, base and quote SPL token-account net deltas agree with direction. `price_quote_per_base` is the **transaction-level net balance ratio**, not an audited per-instruction execution price. Only set `price_sol` when the quote mint is WSOL. These prices **must not be used for backtesting or fill-cost estimates yet**.

Net balance changes can include funding/closing WSOL accounts, side transfers, fees and other transactions within an atomic transaction; no attempt to infer a precise per-instruction price is made. Token amounts are exact decimal integer strings derived using BigInt, without binary floating-point rounding.

## Run on Colima

Update your checkout with `git pull --ff-only origin main` after merge; retain existing `.env` and volumes. Run tests:

```bash
npm test
npm run check
```

S1a and S1b can stay running. Run a separate one-shot decoder container:

```bash
docker compose -f compose.yaml -f compose.s1b1.yaml run --rm --build decode
```

Default max 1000 **newly undecoded hydrated event rows** per run. Raise only for an intentional batch with `S1B1_MAX_EVENTS` in `.env`, up to 100000. Re-running is idempotent; results will not be overwritten by a later decoder version. **No source migrations or drop/recreate.**

## Audit SQL

```sql
SELECT status, dex, count(*) AS event_rows
FROM onchain_trade_decodes GROUP BY status, dex ORDER BY status,dex;

SELECT COUNT(*) AS decoded, COUNT(*) FILTER (WHERE side IS NOT NULL) AS direction_labeled,
 COUNT(*) FILTER (WHERE price_sol IS NOT NULL) AS indicative_sol_ratios
FROM onchain_trade_decodes;

SELECT d.status, COUNT(*)
FROM onchain_trade_decodes d
JOIN onchain_transactions t ON t.signature=d.signature
WHERE t.tx_error IS NOT NULL AND t.tx_error <> 'null'::jsonb
GROUP BY d.status;
```

The last query should show only `failed_onchain` statuses for these events.

## Out-of-scope / next gates

- Pump.fun/PumpSwap v2 and other IDL revisions.
- Atomic instruction-level trade amounts and fee breakdown from verified events or inner token transfer traces.
- Deterministic reconstructed per-instruction fills, normalized minute bars, OHLCV, fee-aware replay.
- Production data coverage and live-vs-backfill continuity.

No S1b.1 output is approved for trading or backtests until real-world spot checks against a block explorer and instruction-level fee-aware reconstruction pass.
