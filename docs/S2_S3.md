# SOLARIS S2/S3 — Research-only risk and strategy pipeline (v0.5.0)

**Status: IMPLEMENTATION CANDIDATE, ECONOMICS NOT AUTHORIZED.** The collector (S1a), Solana streamer (S1b) and on-chain decoder (S1b.1) remain unchanged. No wallet, order signing, swaps, position management or live trading.

## Scope and guarantees

### S2: token/pool concern screen

- Reads latest indexed S1a snapshots and token mint account info using standard Solana \`getAccountInfo\` with \`jsonParsed\`.
- For classic SPL Token mints, verifies that the RPC response is parsed as a mint, checks \`mintAuthority\` and \`freezeAuthority\`. For Token-2022, also inspects available extension identifiers.
- Explicitly rejects low liquidity and enabled authorities; reports unknown/unverified conditions rather than declaring tokens safe.
- **Mint and freeze authority state is a present-day account check, not evidence of its value at pool inception.** S2 results MUST NOT be retroactively used as historical features in S3.
- Cannot validate holder concentration, liquidity burn/lock, proxy contracts, sellability, transfer restrictions across all extensions, or malicious wallet coordination. Those remain \`unverified\`.
- Score is a heuristic *concern score*, not a fraud probability. \`riskBand=review\` is **not approval to trade**. Every row has \`tradability=blocked\` and \`economics_authorized=false\`.
- RPC quota and provider limits apply. The service defaults to 25 newest pools and 1.5 s spacing; retry handling is conservative.

### S3: audit-first strategy research

- **Default** \`S3_EXPLORATORY_PROXY=0\`: only coverage audit; no simulated trades and no reported profit.
- Explicit \`S3_EXPLORATORY_PROXY=1\`: deterministic research using indexed GeckoTerminal observations. Three experimental candidate signals: \`early_momentum\`, \`volume_surge\`, \`buy_pressure\`. These are hypotheses, not validated strategies.
- Historical **signal features** only use observations at or before the signal timestamp. The earliest possible proxy entry is the *next* observed mark; the first qualifying proxy exit is after the requested hold period.
- No interpolation across detected large gaps. Unavailable entry/exit => **censored**, not a loss/win. Exits crossing chronological phase boundaries are excluded.
- Default 300 bps entry slippage, 300 bps exit slippage, 100 bps extra fee stress. These are **assumptions**, not measured Solana liquidity / wallet fees; actual fills can be worse or impossible.
- Three chronological phases: discovery (60%), validation (20%), test (20%) based on observed timestamp distribution. No optimizing thresholds on test data; split is for diagnostic reporting, **not** a claim of out-of-sample validity.
- The dataset is **not survivorship-free** and does not guarantee complete coverage of newly launched tokens. GeckoTerminal snapshot volume is a rolling window; never sum adjacent values as trade volume.
- **Indexed marks are not executable fills**. No shorting, price impact simulation, liquidity depletion, transaction rejection, MEV, priority fee, fee-on-transfer, effective spread or verified on-chain execution economics are represented. \`proxyNetReturn\` is strictly illustrative.

Every S3 run is stored with \`economics_authorized=false\` and status either \`BLOCKED_DATA\` or \`RESEARCH_ONLY_BLOCKED\`, even when the exploratory proxy metrics happen to be positive. No research output can be used to activate trading.

## Setup on macOS + Colima

Keep \`.env\` local and existing Docker volumes intact.

\`\`\`bash
git pull --ff-only origin main
npm install
npm test
npm run check

# S2: token authority / pool liquidity screening, appends derived results only
docker compose -f compose.yaml -f compose.s2-s3.yaml run --rm --build risk

# S3 audit: no proxy trade calculations by default
docker compose -f compose.yaml -f compose.s2-s3.yaml run --rm --build research

# EXPLICIT optional research; never used for live trading:
# Set S3_EXPLORATORY_PROXY=1 in local .env, then repeat "research".
\`\`\`

Optional local env:
\`\`\`dotenv
S2_MAX_POOLS=25
S2_RPC_SPACING_MS=1500
S3_MAX_POOLS=50
S3_MAX_SNAPSHOTS_PER_POOL=500
S3_EXPLORATORY_PROXY=0
\`\`\`

**S2** depends on a configured \`SOLANA_RPC_HTTP_URL\` from your existing S1b environment to gather mint information. Without it, mint checks are marked unknown and trading stays blocked. The S3 runner does not need an API key; it reads snapshots from PostgreSQL.

## Verification SQL

\`\`\`sql
SELECT risk_band, count(*), min(observed_concern_score), max(observed_concern_score)
FROM s2_pool_assessments GROUP BY risk_band ORDER BY risk_band;

SELECT id,created_at,mode,status,economics_authorized,
 report->>'readyPools' AS ready_pools,report->>'proxyCompleted' AS proxy_completed
FROM s3_research_runs ORDER BY id DESC LIMIT 10;

SELECT run_id,ready,count(*) FROM s3_pool_coverage
GROUP BY run_id,ready ORDER BY run_id DESC,ready;

SELECT run_id,strategy,dataset_split,censored,count(*) FROM s3_proxy_trades
GROUP BY run_id,strategy,dataset_split,censored ORDER BY run_id DESC,strategy;
\`\`\`

No database deletion, migration reset, GitHub secrets, S1a restart, or S1b restart is required.

## Required work before S3 can pass an economic gate

1. Upgrade S1b.1 to **audited instruction-level fills** from known DEX events (including current program versions), fees, and token decimals. The S1b.1 \`matched_quote_delta\` ratio is not an audited fill.
2. Build durable, bounded on-chain historical coverage with gap reconciliation and explicit pool selection; recheck program and account layouts on real transactions.
3. Add point-in-time token holder / mint controls / LP verification and realistic sell-side route liquidity. Current S2 mint checks are *now-only*.
4. Capture tradeable quotes or orderbook/AMM state **as actually available at signal time**, quote age, priority fees, price impact, realistic latency, failed transactions and MEV.
5. Fix strategy definitions and stress tests before collecting a long, untouched test window. Validate sufficiently large samples per regime and token launch cohort.
6. Pass independent holdout and forward paper-trading with raw reconciled trade evidence, not just a positive proxy curve.

Until these conditions are met, **S3 is a research framework, not a validated or profitable trading strategy**.
